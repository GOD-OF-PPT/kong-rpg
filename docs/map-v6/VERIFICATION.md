# v6.2.0 地图美术验收

## 预先检查点

1. 美术：试炼/归灯/掉落/特殊地面/地刺在实机尺寸下呈现具体材质和不同轮廓；状态变化保留物件大小和落点。装饰不悬空、不压盖交互主体，不发奖励光。
2. 对齐：平台落脚边缘跟随原坐标，浮筏带人时人物脚底与筏面一起移动；地刺实际绘制像素不超出原危险框。
3. 行为：F归灯只恢复一次、F开启试炼、已清试炼F领奖后显示已领态、灯枢接回既有三段桥；碎台按原时序消失恢复；地刺静息/预警不扣血、激活时接触扣血；三种补给满值留地、资源不足时走近自动拾取。
4. 发行：二十张内嵌图像完整解码，原八条音效仍可解码；1440×1000与1366×768桌面显示、DOM暂停边界、schema6存档导入导出可用。本地HTTP和服务器关闭后的全新断网file会话均检查；file会话HTTP请求为0。

## 方法及可复核证据

`tools/verify-map-art.cjs http`与`file`使用正式发行入口，真实浏览器键鼠，经DOM导入合法场景存档，再通过正式输入和模拟执行。固定种子`MAP-ART-1026`。所有`*-fixture.json`、逐项观察、发行入口SHA256和截图名保留在`evidence/map-v6/`的两个`*-verification.json`。视频路径也写在报告中，原始未剪辑录像保留于本地`video/`，不是真人体验记录。

为审查远处材质、桥和装饰，工具另以正式Renderer绘制固定位置的静态场景并捕获Canvas；报告和工具注释明确区分这些画面与真实输入检查。可领奖的试炼通过合法已清场景存档建立；没有将它记为完整战斗通关。地刺像素边界检查在透明画布上调用同一个正式绘制方法，另用实际移动验证伤害阶段。

`tools/capture-map-comparison.cjs`从基线Git对象读取原发行HTML，与新版采用相同种子、镜头、站立姿态及1.2秒渲染时钟，产生八张严格同条件的前后Canvas对照；源版本哈希见`comparison.json`。代表性对照与交互帧入库，全部截图和录像保留本地；其余画面可用脚本重新生成。`mechanics-unchanged.json`另记录八个玩法、输入、音频和存档模块与基线逐字节相同的SHA。

环境：2026-10-26，Windows 10.0.26200，Intel i5-14600K，Node 22.12.0，Edge 156.0.4314.42。优先目标为PC键鼠，没有扩大移动端适配。

## 本次观察与调整

- 未设计的归灯方块和试炼线条与背景材质断层，已用ImageGen物件替换；同场景可看到檐顶、灯芯、莲座和三棍香炉。
- 初稿装饰严格使用旧地标，部分地标在空隙或实地边缘；仅调整渲染落点到邻近实地，避开主要交互和危险，已复核三境画面。
- 源图并非严格等距格子，首次检查即采用明确源矩形与共用底部锚点，避免裁坏檐顶、朱带或把状态切换画成位置跳动。
- 浏览器初次检查桥时，读状态早于下一次模拟步，产生过验收脚本失败。修正检查等待一次真实更新；游戏逻辑未因此改动。
- 归灯、试炼、碎台、筏、桥、三类补给、地刺、暂停和存档的定向输入检查均通过；素材解码与页面运行无异常。地刺三态像素均位于原60×13检查框内，激活阶段接触实际扣血。
- 图集切片为30个既有元素/状态表现，不是30项新增玩法。`simulation.js`、`world.js`、`journey.js`、`progression.js`、`heroes.js`、`storage.js`与本轮起点保持相同源码；已有规则检查另保留为`rules.json`。

## 交付与边界

源码、源图、归一图、切片、提示词和制作脚本均在仓库。发行HTML使用内嵌data URL；`npm run build`不需要生成接口或Pillow，直接使用已归一的PNG。重新归一才需`python tools/prepare-map-art.py`。

完整包`artifacts/kong-rpg-offline-v6.2.0.zip`保留v1–v5旧入口与音效试听页；包CRC、每个文件和入口哈希见`evidence/map-v6/package.json`。该完整包超过GitHub单文件限制，作为本地交付保留，仓库含全部发行文件。
