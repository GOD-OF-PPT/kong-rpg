基线`0fa74cb93e07aee2761187c240f2c11388fb6590`（v7.1.3），分支`codex/three-heroes-realms-v8`。正式入口SHA256为`f69ba46a6906bde04f750b670dedbf8ac8402d9c0f7ff2d0af578fccaeecd168`。制作目标及实施前门槛见GOAL.md。

## 已实现

### 角色与取舍

哪吒J/左键火尖枪三连，第三枪重击；H/右键单枚乾坤圈，12定力，去回各自去重，环在外仍可近战。H水平出手、右键朝光标，L混天绫与U风火轮保留。对应舍利/法门改为烈枪心、烈枪余焰等实际规则文案。

杨戬J/左键三尖两刃刀，H/右键射雕弓：18定力、0.22秒引弦、0.8秒冷却，普通箭32伤害；引弦受伤取消，不退款；正面盾能挡，破军锋提升为42并破盾。L天眼：30定力、固定区域3秒，照妖眼强化为5秒/360范围；区域内可识破护盾，不能冻结敌人。U为12定力的短神行步。

杨戬R以100战意召哮天犬协战8秒，灵犬追猎强化为10秒。犬追随附近活跃敌人、跳起扑咬，每次18伤害、0.85秒间隔；目标较高时提高扑跃，保留地面/重力和追回玩家的边界。它是持续协战，不是全屏瞬时结算；玩家仍需牵制敌人与躲招。死亡/换境清理协战状态。

悟空的三连、分身、伸棍/撑跃、法天象地继续可选，H/右键为分身（L也保留）。PC键鼠、Canvas世界、DOM复杂阅读、音乐与既有胜负闭环继续使用原架构。

### 场景与敌人

五个新增作战区域位于现有四境连续路段，准确边界在README。它们不是五个新增独立长关；水下以护体通行解释跑跳，不另外引入游泳或氧气管理。

|区域|新怪物主体|普通模式领域招式|
|---|---|---|
|云上断阶|踏云戟卫 / 巡风羽使|巡风横切：锁定高度，弹体沿预告线路前进|
|天宫封廊|镇门天将 / 雷诏司|天诏雷印：锁定一处高印区，移开或打断|
|沉渊水道|钳潮虾卫 / 吐珠蚌妖|潮珠对流：高低两条完整预告路径，相向来珠|
|龙宫珊庭|玄甲蟹将 / 唤潮龙侍|龙宫涌柱：两处预告水柱，留下撤离位置|
|地府忘川|锁魂鬼卒 / 引灯判使|追魂灯印：第一印释放后才重新锁第二印|

这些主体采用原刀/盾/法师碰撞及普通招式骨架，有独立像素轮廓、材质和领域技能。普通模式由术士施放领域招式，近战守卫保留突刺/盾冲；挑战模式更多敌人可参与，但同时最多两名启动领域招式。新技能一般给1秒预警、4.5秒冷却、结束后1.35秒收招；追魂二印另给0.8秒。重击可断普通蓄力。弹体行程在其预告路径内，锁定后不追踪玩家。

### 标识与实际美术

敌人使用1像素暗红外轮廓，保留原材质与动作；攻击时使用玫红的精确危险边线。增益物品用青绿托底括号及加号，葫芦/珠/火焰轮廓与DOM名称共同识别；资源满值时减亮并收起加号。奖励灯仍用金色火焰、借后熄灭；哮天犬使用青色爪印。这样比全身常亮的红/绿粗框更能保留像素画面，也不要求玩家只靠颜色判断。

使用用户指定的内置ImageGen：5幅新背景、哪吒持枪八姿态、杨戬八姿态、犬及箭/天眼等组件、10种怪物、5组平台/墙基。`assets/v8/prompts.json`保存完整提示词，`normalization.json`保存源/成品SHA及裁切尺度；`prepare-v8-art.py`只做裁切、共同比例、nearest-neighbour归一，保留RGBA，不用色键抠底。杨戬首稿长武器相邻格拥挤，第二稿改2列4行后重新切片。暂停与选人使用独立高分辨率源裁片，避免放大小精灵造成模糊。

正式入口包含39张PNG、183条已登记切片，新增V8Frames为44条；构建检查存在、尺寸、边界和锚点，浏览器检查新切片非空、真实解码。角色使用关键姿态切换，不宣称完整逐帧手绘动画。

## 测量和原始证据

环境：Windows 10.0.26200、Edge 156.0.4314.42、1440×1000整局视口，定向界面为1366×768；Node.js v22.12.0。固定种子为`LOTUS-1025`（整局）和`V8-PC-1027`/`V8-RULES`（定向）。报告中保存入口哈希、浏览器版本、输入边界、按键到渲染提交的记录、帧间隔、奖励选择及受伤来源。

杨戬最终离线整局：帧间隔P95约5.7ms，输入到渲染提交P95约10.7ms、最大67.4ms；哪吒为5.7ms、10.6ms、最大52.4ms。这些来自该无头宿主requestAnimationFrame/输入事件，不是屏幕光子延迟，不外推为所有PC的帧率保证。

`offline-full/file-page-recording.mp4`为连续页面截图编码，899帧、约179.8秒，旁边JSON记录真实采集时间；已解码查看水下弓箭和终局犬协战画面。哪吒另有完整页面记录。它们是约5Hz采样的游戏页面录像，不是高帧率运动分析；没有将原生浏览器录像中的下载页当游戏画面。每次只查看1–2张图，关键截图包含选人、暂停、枪击、召犬、五领域和最终结算。

## 修正与保留的失败

早期整局有两次失败：一套策略在第三境封愿光柱前召犬并死亡；另一套死于追魂印。初期规则允许所有近战兵和术士施放领域技能，普通遭遇的锁定区过密，已改为普通模式术士负责、挑战模式扩展。控制器也修正了在预警结束后立即回到仍有效印区的做法，并改在收招窗口召犬。相关失败位于`erlang-run/`、`erlang-retry/`，对应开发版哈希不作为最终版通过证据。

另一次以破军锋起步的控制器在第一境卡住，已中止，未标记为通关。定向脚本曾将杀敌返定力误算为射箭未扣费，以及选中满值定力掉落却要求拾取；均修正验收方法，没有为迎合检查修改资源规则。记录保留在`browser-first-attempt.json`/`browser-second-attempt.json`。

内部实机检查确认：主副武器、领域怪物、标识和读招有可见区别，关键资源没有缺图或越界失败。没有外部真人试玩，不声称三角色平衡、首次辨识或长期耐玩已获得玩家认可。最终整局证据为普通模式两位变更角色；挑战模式和悟空在本版通过规则/存档与局部检查，未将其写成新版本完整通关。
