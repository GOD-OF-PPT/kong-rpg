# 常驻场景物件状态美术补齐 · v7.1.1

基线：`e6bc8515fc89ba266e7aeec40102aaea44cec613`（v7.1.0）；分支：`codex/scene-art-completeness-v7-1-1`。检查范围是四关常驻场景物件的主体、破损和已使用状态；战斗预警、血条与精确落脚边仍由程序绘制。

## 原始问题与修正

- 用户截图中的已毁阵眼只有两个灰色矩形，无法辨认莲瓣、材质和毁坏状态。现用同一图集的碎裂莲座：裂开的莲纹石台、折断晶体、倒伏黑莲瓣。它保持静止、没有奖励火焰，不使用掉落物的浮动反馈。
- 三境首个阵眼借灯后原本也变成灰色块。现保留同一铜碗与碎座，熄灭灯芯并表现烟熏，与可借灯状态保持物体连续性。
- 终局首阵眼错误沿用可借灯造型，实际F逻辑只允许前三境。视觉状态现同样检查`stage < 3`；终局两个阵眼只会显示完整/破碎。
- 发行原来只检查图片文件存在，没有检查地图/变化图集的切片边界。新增构建关卡，对所有内嵌PNG和三套帧表检查资源引用、尺寸、切片及锚点；缺失或越界即中止打包。

## 素材与接线

使用内置ImageGen，参考`assets/art-v2/journey-props.png`及`assets/map-v6/props.png`。完整提示词见`assets/scene-v7/prompts.json`；生成源为`seal-states-source.png`。`tools/prepare-scene-art.py`仅裁切、nearest-neighbour归一及拼接，保留真实RGBA，不进行色键去底。原图和产物SHA、源矩形、共同缩放在`normalization.json`。

四帧归一为64×64，底部锚点`[32,62]`；主体最大60像素宽，与角色和原阵眼规模接近。实际绘制底部始终为`q.y + q.h`，不改变碰撞框、交互距离、掉落、奖励、随机种子、存档schema7或敌招。

`scene-data.js`保存帧表，`scene-art.js`选择状态并绘制主体。图片通过既有打包器内嵌在发行HTML；运行时无图片请求。旧版入口保留原文件。

验收方法：同种子/相机/时钟的前后截图，HTTP与断网file入口中的真实攻击→破阵→F奖励→选择→熄灯，终局破阵不出现借灯，以及全部图集帧非空/切片检查。控制导入用于复现场景，不冒称完整自然通关。主观辨识与外部真人评价单列。
