# v11 战斗修订验收约定

基线201b65e/v10.0.3，分支codex/v11-combat-feedback，起步干净。用户实机反馈：悟空/杨戬H与L像同一技能；首领太弱；哪吒R没有强化且缺打击感；命中特效有瑕疵。

修前原始探针 `node tools/probe-combat-v11.cjs`：悟空H/L均分身；杨戬H发箭而L天眼；哪吒R实际64伤害但无持续加成；哪吒站桩J/R可在4.7–8.8活动秒击败五名大首领。见evidence/combat-v11/before/probe.json。

修订范围与通过标准：

- H与L在角色能力、消耗和画面上独立：悟空H为定向破空棍劲、L分身；杨戬H射雕弓、L天眼，均单独按键与鼠标副攻验证，L不得顺带射箭。
- 哪吒R有真实范围伤害及4秒莲火附枪，主武器有效命中额外伤害；HUD显示剩余时间；不能凭特效认为加成存在。未命中不能发命中爆点。加成/副攻状态导出恢复一致。
- 首领保持300起的原生命，不以统一堆血制造难度。移除每次大招必打断首领的循环；正面架势、收招破绽、低血追击和远距应对须明确预警。站桩J/R对照需明显差于看招闪避/绕背/破机关策略；五位均要实际出招、可反制，挑战二段仍有独立预警。
- 打击特效以实际接触点、武器方向、伤害时刻为依据，轻/重/挡/神通区分；不拉伸大面积火片遮住敌人和危险。检查左右朝向、空中、相机移动、屏震和同帧多目标。
- 本地HTTP与关闭服务器后的断网file都实际键鼠运行；完整首领对照、暂停/焦点边界、存档与旧版保护要有记录。

战斗规则改变将以独立v11/schema11保存，保留真实v10.0.3原入口legacy-v10.html供进行中的旧旅程继续。不能把v10已有整局证据算成v11验收，也不将自动控制器当真人主观评价。

## 反例后的收紧

初版仅比较站桩J/R不足：加入“只追着首领、技能到冷却即用、不读预警”的控制器后，首轮模拟30/30取胜。原条件被此反例推翻，不能宣称首领难度已解决。

修订目标改为：相同条件下，追打策略胜率低于一半，读招策略至少九成，读招平均受伤少于追打；保留部分局面能付出生命代价强攻的选择。只用于这批固定场景的规则比较，不能外推真人胜率。调整撤步、收招及重招代价后，再做实际键鼠和整局验证。首轮结果和控制器失败均保留，不把失败删成通过。
