# v6.0.2：地面补给的拾取反馈

基线 `8adf2c5` / v6.0.1。用户截图中的金色莲状物与战意火的旧渲染相符；截图没有HUD，不能单凭图片确认当时的战意值。

## 复现与原因

固定种子 `LOTUS-1025`，击败真实生成的首名敌人，得到金色战意火；通过正常JSON导入场景后，实际按D走到道具上。战意100时角色和道具碰撞框重叠，掉落仍未使用、没有拾取事件或满值解释。仅把战意改为50，在同一位置正常拾取至64。生命、定力补给同样在满值时保留，不足时自动拾取。

根因：v5起采用“资源满时保留补给”的规则，但 `collectPickup` 直接返回，界面没有说明；三种补给还被画成相似莲花。原本用于区分药品、定力和战意的图标在 `combatCues` 中过早绘制，随后被通用莲花盖住。实际走过完整碰撞范围可拾取，未发现碰撞失效。

## 修正

- 靠近补给显示名称、用途和原因，例如“战意火 · 战意已满（100/100）· 先用R大招”；资源有空时显示走近自动拾取。满值保留规则不变，无需按F。
- 类型图标在真实拾取物图层只绘制一次，使用药品十字、定力菱形、战意火焰；对应资源满时降低亮度。
- 显示与结算共用 `pickupInfo`，包括金刚筋增加后的生命上限。部分补充只显示实际所得，例如139/140拾取后显示生命+1。

## 验证

复现命令：设置项目既有Playwright的NODE_PATH后运行 `node tools/pickup-feedback-v6.cjs http`。修改前已实际失败于“满战意时没有说明”，保留 `before.json`；修正后HTTP与全新断网file均通过：三种满值保留及原因、三种缺资源自动拾取、只结算一次，以及真实按R后原金色补给自动拾取并恢复14战意。断网页面零HTTP(S)请求、零异常。

`npm run verify` 通过既有规则与新增140生命上限/实际恢复量回归。原始场景、位置、事件、截图和版本哈希见 `evidence/ranged-v6/pickup-6.0.2/`。这是拾取问题的定向复核，不冒充新一轮完整通关或真人体验。存档仍为schema6，未增加存档字段。
