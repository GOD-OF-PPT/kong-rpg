# 资源加载性能修正

基线e947f438d9eb91dd3d7e3a5880b23e8f98f218b2 / 12.3.0。问题截图generated-art.js 59,854kB、34.52秒；本机实际HTTP路径复现59,853,498字节，generated-music.js另有15,855,390字节。前一轮素材目录清理没有改变这条网络加载路径。

事先验收：网络版generated-art.js≤32KiB、generated-music.js≤4KiB；资源不可再以整包base64脚本阻塞页面。以2MiB/s、20ms RTT、禁用缓存的新Edge会话比较菜单可用且背景/字标绘制完成时间，目标≤6秒、首屏≤5MB；菜单不下载其它区域/战斗图集。开始、继续或导入时有真实加载进度，资源失败可重试，不把缺图几何后备算可用。跨区域和三英雄必须加载其所需素材后才进入模拟。

假设依优先级：1. base64把图片当脚本统一传输是主要体积与解析成本；2.首屏等待所有图集而不是当前界面；3.长音乐也被整包编码到阻塞脚本；4.预览服务器无压缩/缓存/音频Range放大冷/热加载成本。以同一网络条件的资源体积和时间检验，不把本机结果当作用户网络复现的34.52秒。

实现保持Canvas/DOM与现有模拟，不换引擎。HTTP使用独立缓存图片和按需音乐；Web发行可用无损WebP等价导出，原成品PNG继续用于独立单HTML离线版。file入口仍需在断网、新会话下真实运行，资源不依赖CDN/远程字体/缓存。版本、截图、错误、丢包重试与冷热请求记录存evidence/loading-perf。
